# Phase 1 UI/UX audit

17 November 2026. Scope: the existing 22-route React/Vite site, mounted route components, shared UI, four imported CSS files, Tailwind usage and the previous browser captures. No rebuild or deployment.

| Finding | Evidence | Phase 1 correction |
| --- | --- | --- |
| Reading hierarchy is too small | Shared body is 15px; many descriptions are 11–14px; mobile rules reduce them further. Footer/labels often use 9–11px. Existing Inter/Jakarta fonts already suit the brand. | Fluid heading scale, 16–18px reading copy, 14px actions/metadata, retained compact illustrative dashboard typography. |
| Spacing has several competing scales | Sections use 80px desktop/54px mobile, page heroes 58/40px, CTA 66/50px; gaps vary independently. | Shared container, section, gap, radius and control tokens; 104px desktop, 80px tablet, 64px mobile section rhythm. |
| Weak section transitions | FAQ and Insights both use white; company and process repeat the soft background. CTA and footer share a background with only a line between. | Coordinated white/soft sequence, a navy company feature, soft Insights and a larger footer transition. No border around every section. |
| Dense service and supporting content | Homepage primary service panels are only 8px apart; supporting services and six desktop process columns contain small text. | Separate service panels with 24px gutters, larger reading type, three-column process at intermediate widths and two/one-column mobile treatments. |
| Image/text balance | Hero montage has three competing images; portrait/landscape assets use a mix of fixed heights and aspect ratios. Existing assets are clearly disclosed illustrative concepts. | Preserve the montage but give its main image priority; consistent 3:2 illustrative wrappers and 16:10 hero main image, natural page section heights. |
| Uneven card actions | Natural text lengths can place service/course actions at different heights. Some card types are deliberately editorial rather than boxed. | Flex-column alignment for service cards with action groups at the end; retain alternating work studies, accordions and editorial lists. |
| Navigation feels undersized | Desktop navigation is 12px, CTA 11px; existing keyboard Services disclosure and mobile menu already work. | 14px links, 48px CTA, clearer active/hover states, scroll shadow, scrollable mobile menu and outside-click/route-change dismissal. |
| Contact reading density | Labels are 11px and panel copy 12px; input font increases only on mobile. Tablet contact columns squeeze the form. | Consistent 16px inputs, 14px labels, generous gaps, single-column contact at tablet widths. Preserve disabled-until-hydrated POST privacy protection. |
| Mobile float can obscure copy on other routes | Existing Training capture shows the fixed WhatsApp icon above body content; Contact already omits it. | Give mobile pages an inline footer WhatsApp route instead of a floating overlay; retain desktop float and Contact's two inline actions. |
| Breakpoint maintenance | The final responsive file contains many small-font overrides. Tailwind remains mostly in the not-found layout and dormant legacy components. | Keep the current architecture; consolidate the foundations and add a clearly scoped refinement stylesheet after legacy responsive rules. Do not restyle illustrative UI as website text. |

No horizontal overflow, broken images or contrast failures were reported in the preceding production verification. Those are regression checks, not invented audit defects. Unused legacy sections (Stats, Testimonials, etc.) are not mounted and do not affect the current layout; leave them outside this phase. Existing routes, metadata, sitemap, Vercel configuration and contact integration must remain unchanged.
